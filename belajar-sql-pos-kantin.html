Studi kasus POS kantin

POS (Point of Sale) mencatat produk, kasir, transaksi, dan detail barang yang dibeli.

MASTER

products

Kode, nama, harga, stok, kategori, dan status produk.

HEADER

sales

Nomor invoice, kasir, total, metode bayar, dan status.

DETAIL

sale_items

Produk, jumlah, harga satuan, dan subtotal per baris.

Relasi sederhananya

Entity relationship
categories  1 ─── N  products
cashiers    1 ─── N  sales
sales       1 ─── N  sale_items  N ─── 1  products

Contoh data awal menyediakan delapan produk, dua kasir, empat transaksi, dan sebuah view laporan bernama v_ringkasan_penjualan.

01

UPDATE — mengubah data

Digunakan ketika baris sudah ada, tetapi satu atau beberapa nilainya perlu diperbarui.

Pola dasar
SQL
UPDATE nama_tabel
SET kolom_1 = nilai_baru,
    kolom_2 = nilai_baru
WHERE kondisi;

Kasus 1 — harga Nasi Goreng naik menjadi Rp16.000

Periksa dahulu baris yang akan berubah, lalu jalankan UPDATE dengan primary key.

Preview + update
SELECT product_id, product_name, price
FROM products
WHERE product_id = 1;

UPDATE products
SET price = 16000.00
WHERE product_id = 1;

Kasus 2 — stok bertambah setelah belanja bahan

Nilai relatif
UPDATE products
SET stock = stock + 10
WHERE product_code = 'MNM-003';

Kasus 3 — ubah beberapa kolom sekaligus

Multiple columns
UPDATE products
SET product_name = 'Es Teh Lemon',
    product_description = 'Teh dingin dengan lemon segar',
    price = 7000.00
WHERE product_code = 'MNM-001';
Jangan lupa WHERE.UPDATE products SET price = 16000; akan mengubah harga seluruh produk. Jika memang ingin mass update, tulis dan periksa kriterianya secara eksplisit.
02

DELETE — menghapus baris

DELETE menghapus data, bukan struktur tabel. Efeknya dapat permanen setelah COMMIT.

Pola dasar
SQL
DELETE FROM nama_tabel
WHERE kondisi;

Kasus — hapus transaksi yang sudah VOID

Safe delete
-- 1. Preview target
SELECT sale_id, invoice_no, status
FROM sales
WHERE sale_id = 4 AND status = 'VOID';

-- 2. Hapus hanya jika benar-benar VOID
DELETE FROM sales
WHERE sale_id = 4 AND status = 'VOID';

Foreign key sale_items.sale_id memakai ON DELETE CASCADE. Karena itu, detail barang milik transaksi tersebut ikut terhapus otomatis.

Alternatif yang lebih aman — soft delete

Untuk produk yang pernah masuk transaksi, biasanya jangan dihapus. Nonaktifkan saja agar riwayat laporan tetap utuh.

Soft delete
UPDATE products
SET is_active = FALSE
WHERE product_id = 8;

-- Menu kasir hanya menampilkan produk aktif
SELECT * FROM products
WHERE is_active = TRUE;
DELETE tanpa WHERE = seluruh isi tabel hilang.DELETE FROM sales; menghapus semua transaksi yang tidak terhalang relasi atau constraint.
03

Transaction — satu paket kerja

Sekelompok query yang harus dianggap sebagai satu kesatuan: semuanya berhasil atau semuanya dibatalkan.

START
Kunci stok
Simpan penjualan
Kurangi stok
COMMIT
PerintahFungsiKapan dipakai
START TRANSACTIONMemulai transaksi.Sebelum query yang saling bergantung.
COMMITMenyimpan semua perubahan.Jika seluruh langkah berhasil.
ROLLBACKMembatalkan perubahan sejak transaksi dimulai.Jika stok kurang atau terjadi error.
SAVEPOINTMembuat titik pemulihan di tengah transaksi.Untuk alur transaksi yang lebih panjang.

Kasus lengkap — pelanggan membeli 2 Nasi Goreng

Checkout transaction
START TRANSACTION;

SET @product_id = 1;
SET @qty = 2;
SET @unit_price = 15000.00;
SET @total = @qty * @unit_price;

-- Kunci baris agar stok tidak dipakai transaksi lain bersamaan.
SELECT product_id, product_name, stock
FROM products
WHERE product_id = @product_id
FOR UPDATE;

-- Kurangi stok secara atomik. Jika ROW_COUNT() = 0, jalankan
-- ROLLBACK dan jangan lanjutkan karena stok tidak cukup.
UPDATE products
SET stock = stock - @qty
WHERE product_id = @product_id
  AND stock >= @qty;

SELECT ROW_COUNT() AS stock_updated; -- Harus bernilai 1.

INSERT INTO sales (
  invoice_no, cashier_id, subtotal, discount, total,
  payment_method, amount_paid, change_amount, status
) VALUES (
  CONCAT('INV-', UUID()),
  1, @total, 0, @total, 'CASH', 50000, 50000 - @total, 'PAID'
);

SET @sale_id = LAST_INSERT_ID();

INSERT INTO sale_items (sale_id, product_id, quantity, unit_price)
VALUES (@sale_id, @product_id, @qty, @unit_price);

COMMIT;
Jika stok kurang atau ada query gagal, jalankan ROLLBACK.Gunakan tabel ber-engine InnoDB agar transaction dan row locking bekerja. Dalam aplikasi nyata, kode backend wajib memeriksa hasil UPDATE sebelum COMMIT.

Eksperimen ROLLBACK yang aman

Try it
START TRANSACTION;

UPDATE products
SET price = 999999.00
WHERE product_id = 1;

SELECT product_id, product_name, price
FROM products WHERE product_id = 1;

ROLLBACK;

-- Harga kembali seperti sebelum transaksi.
SELECT product_id, product_name, price
FROM products WHERE product_id = 1;
04

ALTER TABLE — mengubah struktur

Berbeda dari UPDATE yang mengubah isi baris, ALTER TABLE mengubah bentuk atau aturan tabel.

Gunakan tabel products_practice.File database menyediakan salinan khusus latihan agar tabel products utama tidak rusak.

Ganti nama kolom sekaligus tipe datanya

CHANGE COLUMN
ALTER TABLE products_practice
CHANGE COLUMN product_description item_description TEXT NULL;

Ganti beberapa kolom dalam satu perintah

Multiple changes
ALTER TABLE products_practice
  CHANGE COLUMN product_name item_name VARCHAR(120) NOT NULL,
  CHANGE COLUMN stock current_stock BIGINT UNSIGNED NOT NULL DEFAULT 0;

Ubah tipe data tanpa mengganti nama

MODIFY COLUMN
ALTER TABLE products_practice
MODIFY COLUMN product_name VARCHAR(150) NOT NULL;

Tambah dan hapus kolom

ADD / DROP
ALTER TABLE products_practice
ADD COLUMN barcode VARCHAR(50) NULL AFTER product_code;

ALTER TABLE products_practice
DROP COLUMN barcode;

Tambah dan hapus UNIQUE constraint

Constraint
ALTER TABLE products_practice
ADD CONSTRAINT uq_practice_product_name
UNIQUE (product_name);

-- Di MySQL, UNIQUE constraint dihapus melalui nama index.
ALTER TABLE products_practice
DROP INDEX uq_practice_product_name;
Koreksi dari catatan awal.DROR CONSIBATNT bukan sintaks SQL. Untuk UNIQUE di MySQL gunakan DROP INDEX nama_constraint; untuk foreign key gunakan DROP FOREIGN KEY nama_constraint.

Reset tabel latihan

Reset
DROP TABLE IF EXISTS products_practice;
CREATE TABLE products_practice LIKE products;
INSERT INTO products_practice SELECT * FROM products;
05

INDEX — mempercepat pencarian

Index mirip daftar indeks buku: database dapat menemukan baris tanpa membaca seluruh tabel.

Pencarian nama produk

Index-friendly search
-- Index ini sudah dibuat oleh kantin_pos.sql:
-- CREATE INDEX idx_products_name ON products(product_name);

SHOW INDEX FROM products;

EXPLAIN
SELECT * FROM products
WHERE product_name LIKE 'Nasi%';
Posisi wildcard penting.LIKE 'Nasi%' umumnya dapat memakai B-tree index. LIKE '%Nasi%' memiliki wildcard di depan sehingga index biasa sering tidak dapat dimanfaatkan secara optimal.

Contoh siklus buat, cek, lalu hapus index

Index lifecycle
CREATE INDEX idx_products_price
ON products(price);

SHOW INDEX FROM products;

EXPLAIN
SELECT product_name, price
FROM products
WHERE price BETWEEN 5000 AND 12000;

DROP INDEX idx_products_price ON products;
-- Alternatif MySQL:
-- ALTER TABLE products DROP INDEX idx_products_price;
Cocok diberi indexTidak selalu cocok
Kolom yang sering dipakai di WHERE, JOIN, ORDER BY.Tabel sangat kecil yang jarang dicari.
Foreign key dan kolom dengan variasi nilai tinggi.Kolom boolean tunggal dengan nilai hanya 0 dan 1.
Pencarian invoice, kode produk, atau rentang tanggal.Terlalu banyak index pada tabel yang sering INSERT/UPDATE.

07

Uji pemahaman

Coba tulis query sendiri sebelum membuka jawabannya.

1. Harga “Kopi Susu” berubah menjadi Rp9.000. Query apa yang digunakan?

UPDATE products SET price = 9000.00 WHERE product_code = 'MNM-002';

2. Bagaimana menonaktifkan “Pisang Goreng” tanpa menghapus riwayatnya?

UPDATE products SET is_active = FALSE WHERE product_code = 'SNK-002';

3. Kapan ROLLBACK digunakan dalam proses pembayaran?

Gunakan ROLLBACK jika salah satu langkah gagal—misalnya stok tidak cukup atau INSERT detail penjualan error—agar header penjualan dan perubahan stok tidak tersimpan sebagian.

4. Mengapa query LIKE '%Teh%' kurang ideal untuk B-tree index biasa?

Karena wildcard berada di awal. Database tidak memiliki awalan pasti untuk melakukan pencarian terarah pada B-tree dan sering harus memindai lebih banyak baris.
